# D-03, D-04: joining with a join code and by the QR link – 2026-10-26

The join protection of FR-GATH-05, FR-GATH-18 to FR-GATH-21 through the app's own screens: a campfire with a spoken join code, joined from the list with a wrong and then the right code, and by the join link; then a QR-only campfire joined by its link. **Result: the code path passes; the link path passes when the link is handed to the app over adb. D-04 with the camera app (run 3) reached the join page, whose *Open in Zangbundel* goes to Play for a debug build, because the page pins the release application ID; D-04 stays open until a release-ID build is on a phone.**

| Field | Value |
|---|---|
| Scenarios | D-03 (join code variant), D-04 (link part only) (`design/test-plan.md` section 4) |
| Build | `0.1.0`, build type `debug`, BLE protocol v0.30, guiDesign v0.25 |
| Participants | 1, the agent driving the owner's phones over adb |
| Conditions | Indoors, phones side by side on the desk, on USB, screens on |
| Leader | Samsung Galaxy A52, Android 14, setlist *Voorbeeldavond* (9 songs) |
| Singers | Samsung Galaxy S23, Android 16; Huawei Mate 20 Lite, Android 10 |

## Run 1: join code (14:10–14:15)

| Step | Result |
|---|---|
| Start | *Wie mag meedoen* → *Met een deelnamecode*; the leader bar read `Kampvuur 26 okt · lam-beek · 0 zangers · 0:00` |
| QR screen | the QR code with *Kampvuur 26 okt*, *lam-beek* and *Deelnamecode: 8327*; decoded from a screenshot with ZXing to the `https://pe1mew.github.io/Zangbundel/j/#…` link |
| S23, home | card *Kampvuur 26 okt*, `lam-beek · Dichtbij`, lock |
| S23, wrong code `1234` | the leader answered `WRONG_CODE`; the dialog came back over the singer page with *De leider heeft de code niet aangenomen*; strip `lam-beek · verbinden…` |
| S23, right code `8327` | registered; strip `verbonden`, leader bar *1 zanger* |
| Huawei, link (cold start) | the app skipped the welcome screen and opened the joining screen: *Deelnemen*, the name, *lam-beek*, *Gevonden, controleren…*; registered about 15 s after the link without asking for the code; strip `Kampvuur 26 okt · lam-beek · verbonden` |
| S23, link with one byte of the key changed | refused as malformed (the identifier no longer matches the key, BLE protocol 6.5), with the notice *Deze QR-code is geen Zangbundel-kampvuur*; nothing else happened |

## Run 3: the camera app (14:29–14:31), D-04

The owner scanned the A52's QR screen (join code 5423, *zwaluw-borstel*) with the S23's camera app, Zangbundel closed on the S23.

| Step | Result |
|---|---|
| Camera app | recognised the code at once and offered the `https://pe1mew.github.io/Zangbundel/j/#…` link in its *Koppeling* sheet |
| *Koppeling openen* | Chrome, not the app: the App Link is not verified, as expected until `assetlinks.json` carries the Play signing key (RUNBOOK Step 5c) |
| Join page | *Je bent uitgenodigd voor het kampvuur: Kampvuur 26 okt*, read from the link on the phone, with *Open in Zangbundel* and *Installeren via Google Play* |
| *Open in Zangbundel* | **the Play Store**, "Item niet gevonden". The page's `intent://` link names `package=nl.pe1mew.zangbundel.app`; the debug build is `nl.pe1mew.zangbundel.app.debug`, so Chrome treats the app as absent and takes the Play fallback, where nothing is published yet |

**D-04 result: open.** The camera and the page behave as designed, but the last step can only be shown with a build under the release application ID (a signed release or internal-test build), or with a page that does not pin the package. The app's own handling of the link is shown by runs 1 and 2.

**Fixed after the run:** a test build marks its join link with `?app=debug` or `?app=fieldtest` (BLE protocol 6.5) and the join page pins that build's package; checked locally under an Android user agent (no mark, `debug`, `fieldtest`, and an unknown or extended mark, which keep the release package). D-04 is to be run again once the page is live on GitHub Pages.

## Not covered

- *Dit is niet het kampvuur van de QR-code* needs a second leader that copies the identifier with another key; the unit test `JoinProtectionTest` covers it in simulation.
- The similar-name warning needs two campfires with nearly the same name in range, which D-23 prevents on one desk; `NearlySameNamesTest` covers the rule.
- App Link verification and the step from the join page into the app (run 3; needs the release application ID).
