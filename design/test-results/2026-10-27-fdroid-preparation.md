# F-Droid preparation: G-07 on a second machine, signing – 2026-10-27

Preparation for F-Droid (`docs/FDROID-RUNBOOK.md` Steps 5 to 8), which the owner submits with the first production release. Commit `fb6fea5` (versionName 0.1.1; `android/` unchanged since the release commit `6faaf6f`). **Result: G-07 pass on two machines after one fix; the signing procedure works with apksigner 34.**

| Check | Result |
|---|---|
| **G-07, PC against CI** | CI's unsigned release APK of `fb6fea5` (run 40582059450, Ubuntu, no NDK): 5 715 114 bytes, SHA-256 `1a54e632bd5e03a7…24adf0c67`. The same commit cloned fresh with `core.autocrlf=false` and built on the owner's PC (`assembleRelease`, `--no-build-cache --no-configuration-cache`, Temurin 17.0.20): 5 474 994 bytes, different. Of 483 entries only the twelve `lib/<abi>/*.so` differed (libsodium, libjnidispatch, libdatastore_shared_counter): the PC has NDK 27.0.12077973, so the Android Gradle Plugin stripped their debug symbols; CI has none and packs them as published. **Fail**, fixed below |
| **The fix** | `jniLibs.keepDebugSymbols += "**/*.so"` in `android/app/build.gradle.kts`. Rebuilt in the clean clone with the line: 5 715 114 bytes, SHA-256 `1a54e632…24adf0c67`, **byte-identical** to CI's. Line endings made no difference with an LF checkout. **Pass**. CI's next build of a commit with the line should give the same SHA-256, since the line changes nothing when no NDK is present: check it after the push |
| **VCS info** | `META-INF/version-control-info.textproto` holds `generate_error_reason: NO_SUPPORTED_VCS_FOUND` in both builds: the plugin finds no repository at `android/`. Deterministic; architecture section 9 said VCS info was off and now says this |
| **Signing with apksigner** | The unsigned APK signed with a throwaway test key, then the signing block and its padding cut out again as `apksigcopier` does (a scratch script) and compared with the unsigned APK. apksigner **34.0.0** with `--v1-signing-enabled false`: 3 128 bytes of zero padding and a 4 096-byte signing block, everything else identical, v2 and v3 verified. **Pass**. apksigner 36.0.0: entries re-aligned from byte 285. apksigner 34 with v1 on: `MANIFEST.MF`, `.SF` and `.RSA` added. Both are unusable for F-Droid's signature copy, as F-Droid's Reproducible Builds page warns for versions after 34 |
| **Store metadata** | `bash scripts/store-metadata.sh` wrote `fastlane/metadata/android/` from `docs/store-listing/`: titles 10, short descriptions 73 (en) and 75 (nl), release notes 155/275 (en) and 163/303 (nl) characters, five screenshots, icon and feature graphic; `--check` passes, and fails after a hand edit of `title.txt` |
