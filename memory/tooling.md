- **BLE sequence diagrams for the technical design** in `design/ble/`: seven scenarios (start, join, push, repair, leave, end, helper-code delegate) as `.puml`, `.svg`, `.png`; render with the PlantUML jar from `C:\Users\drasv\github\greenhouse-Controller\design\plantuml.jar` on Java 8 with `-charset UTF-8`, one run per format (`-tsvg`, then `-tpng`).
- **App icon decided 2026-10-22:** proposal 06 "Vuurboek in de kring" (seven singers in a half circle behind a yellow-red fire rising from an open white songbook with black lines, Bluetooth sign without ripples in the top left, night-blue background), replacing proposal 02 "Kring van zangers" of 2026-10-18. Master and launcher layers in `design/icon/`, Play PNG in `docs/store-listing/graphics/`. Rasterising SVG: simplest is headless Edge (`msedge --headless=new --disable-gpu --hide-scrollbars --user-data-dir=<scratch profile> --window-size=W,H --screenshot=<file> file:///…svg`), with Windows backslash paths for the profile and screenshot (forward slashes silently wrote nothing), one Edge run at a time; then Pillow `.convert("RGBA")` for Play's 32-bit PNG. The older route works through the browser pane: serve the repo with the `repo-root` launch config, draw the SVG on a canvas from an HTML page on the same origin, save the data URL; the SVG document itself has no HTML canvas. A feature graphic (1024 × 500, same artwork plus name and tagline) is rendered too. Still to upload on Play: the icon and the feature graphic; screenshots need the app. Pulling a rendered PNG out of the browser pane: run a tiny Python server with a POST handler on the repo (scratchpad `save-server.py` pattern), serve the HTML page from the same origin, and POST the canvas blob; returning base64 through the tool result is too large.
- **Play Console quirks learned:** checkboxes and radios set by script do not reach the form model, use real clicks; the browser coordinate frame is 800 wide while the page is 880 wide (scale 0.909); the "Tags" dialog markup is always in the DOM, so `[role=dialog]` is not a reliable open-dialog test; a stale ref clicks the wrong spot after the layout shifts, recompute from a fresh screenshot.
